# ShipLoad

Браузерное приложение для работы с загрузкой, осадкой, дифферентом и остойчивостью судов.

> **Статус безопасности: разработка.** ShipLoad не является одобренным судовым загрузочным прибором и не должен использоваться для разрешения погрузки, выхода в море, балластных операций или других решений, влияющих на безопасность. Результаты требуют независимой проверки по одобренной документации конкретного судна и действующим судовым процедурам.

## Цели проекта

- Отдельный версионируемый технический профиль каждого судна.
- Загрузка судовых документов и извлечение предварительных данных со ссылками на источники.
- Обязательная проверка человеком извлечённых характеристик, таблиц, единиц и диапазонов.
- Формирование загрузочных состояний из lightship, грузов, танков и запасов.
- Расчёт водоизмещения, центров тяжести, осадки, дифферента, влияния свободных поверхностей и показателей остойчивости по проверенным данным конкретного судна.
- Воспроизводимость расчётов: сохранение входных данных, версии ПО, происхождения данных и статуса проверки.

## Архитектура

- `frontend/`: React + TypeScript + Vite, браузерный интерфейс на русском языке.
- `backend/`: Python + FastAPI, SQLAlchemy и расчётные сервисы.
- `backend/migrations/`: миграции Alembic.
- `docs/`: архитектура, модель предметной области, требования безопасности и валидации.
- Локальная база SQLite хранит структурированные данные. Оригиналы PDF и DOCX хранятся в `backend/data/documents/`, вне публичной директории frontend.

Разбор документов отделён от расчётного ядра. OCR/LLM могут предлагать значения, но не могут незаметно превращать их в утверждённые исходные данные.

## Текущая реализация

- Русскоязычный адаптивный интерфейс рабочего пространства, реестр судов и форма чернового загрузочного условия с несколькими строками нагрузки.
- Создание судна начинается с пустого черновика: размерения и координатная система могут отсутствовать до загрузки и проверки документации.
- Загрузка PDF/DOCX-документов по судну: проверка сигнатуры и структуры, ограничение 25 МБ на файл, SHA-256, защита от повторной загрузки, хранение оригинала и выдача оригинала для просмотра.
- Подготовка черновика расчёта из нескольких документов: табличное загрузочное условие из DOCX, гидростатика из текстового PDF и KN-кривая из таблицы остойчивости в DOCX. Значения и строки источника подставляются в форму; неоднозначность между несколькими загрузочными таблицами показывается пользователю.
- Для импорта обязательна ручная отметка, что значения и единицы сверены с оригиналами. Импорт не утверждает данные автоматически; сканы, графики и изображения по-прежнему требуют OCR/проверки.
- Извлечение кандидатов LOA, LBP, moulded breadth и moulded depth из текстового слоя PDF с номером страницы и исходным фрагментом; кандидаты не утверждаются автоматически.
- Ручная проверка кандидатов: подтверждение/отклонение, возможность исправить значение, обязательная метка проверяющего и комментарий.
- Каждое решение сохраняется отдельной неизменяемой записью аудита с исходным и принятым значением, страницей, фрагментом, временем и проверяющим.
- Подтверждённые характеристики создают новую неизменяемую ревизию исходных данных судна; профиль-черновик напрямую не перезаписывается.
- Сканированные PDF помечаются `OCR_REQUIRED`; OCR пока не подключён. Координатная система не угадывается.
- FastAPI: health/status endpoints.
- API реестра судов: создание, список и получение профиля.
- API и интерфейс для сохранения/просмотра черновых загрузочных условий с несколькими строками нагрузки.
- Реестр танков судна в API и интерфейсе: тип, идентификатор, название, документ-источник и опциональная номинальная вместимость с обязательной ссылкой на источник.
- В форме загрузочного условия можно выбрать зарегистрированный танк для жидкой нагрузки; массу пользователь вводит вручную со ссылкой на проверенный источник, без автоматического пересчёта замера.
- Проверка привязки жидкой нагрузки к существующему танку того же судна и соответствию типа танка.
- SQLAlchemy-модель и Alembic-миграция таблицы судов.
- Alembic-миграции `0006_candidate_review_revisions` и `0007_candidate_decision_revision` добавляют журнал решений, ревизии исходных данных и точную ссылку из каждого решения на созданную ревизию.
- По умолчанию используется постоянная локальная SQLite-база: `backend/data/shipload.db`.
- Путь к базе можно переопределить через `DATABASE_URL`; это оставляет возможность перейти на PostgreSQL.
- Новые профили судов имеют статус `DRAFT`; это не означает утверждение технических характеристик.
- Защищённая линейная интерполяция таблиц: запрещена экстраполяция и отклоняются некорректные таблицы.
- Сквозной расчётный сценарий из интерфейса: масса и координаты lightship/нагрузок, свободные поверхности и таблица гидростатики с обязательными ссылками на источники.
- Расчёт водоизмещения, LCG/TCG/VCG, исправленной VCG/GM, осадок, дифферента и начального крена; экстраполяция за гидростатическую таблицу блокируется.
- При наличии исходной KN-кривой вычисляются табличные GZ, динамические плечи и площади под кривой без автоматического нормативного заключения.
- Каждый запуск записывается как неизменяемый снимок входов, источников, результата, ревизии и версии метода; его можно открыть из истории и распечатать / сохранить в PDF через браузер.

Пока не реализованы: аутентификация и разграничение доступа (метка проверяющего сейчас вводится вручную и не подтверждает личность), OCR сканов, семантический импорт калибровочных таблиц танков/трюмов, автоматическое утверждение координат и datum, критерии IMO/Class, погодный критерий, ветер, заливание, пределы прочности, погружение винта и автоматическая оптимизация загрузки. Учебный пример служит проверкой реализации методики и не является одобренным судовым расчётом.

## Локальный запуск

Требуются Python 3.12+ и Node.js 22+.

### Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
alembic upgrade head
uvicorn app.main:app --reload
```

По умолчанию база создаётся в `backend/data/shipload.db`. Переменную `DATABASE_URL` задавать не требуется.

Проверка API: `http://127.0.0.1:8000/health`

API судов:
- `POST /api/v1/vessels` — создать профиль судна со статусом DRAFT.
- `GET /api/v1/vessels` — список судов.
- `GET /api/v1/vessels/{vessel_id}` — получить профиль судна.
- `POST /api/v1/vessels/{vessel_id}/documents` — загрузить PDF/DOCX, поле `file` и необязательное `document_type` (`ship_particulars`, `stability_booklet`, `general_arrangement`, `lines_plan`, `other`).
- `POST /api/v1/vessels/{vessel_id}/calculation-import` — принять 1–8 PDF/DOCX в поле `files`, сохранить оригиналы и вернуть частично или полностью заполненный черновик расчёта с источниками и списком недостающих полей.
- `GET /api/v1/vessels/{vessel_id}/documents` — список документов.
- `GET /api/v1/documents/{document_id}/candidates` — кандидаты извлечённых характеристик с номером страницы, исходным фрагментом и статусом проверки.
- `POST /api/v1/documents/{document_id}/candidates/{candidate_index}/decision` — зафиксировать `APPROVE` или `REJECT`; при подтверждении можно передать исправленное `approved_value` в метрах и `reviewer_label`.
- `GET /api/v1/vessels/{vessel_id}/data-revisions` — список неизменяемых ревизий подтверждённых исходных данных и provenance.
- `GET /api/v1/documents/{document_id}/file` — открыть сохранённый оригинал PDF.
- `POST /api/v1/vessels/{vessel_id}/tanks` — зарегистрировать танк судна; вместимость необязательна, но при её указании обязателен источник.
- `GET /api/v1/vessels/{vessel_id}/tanks` — список танков судна.
- `POST /api/v1/loading-conditions` — сохранить черновое загрузочное условие и его элементы; ссылки на жидкие нагрузки проверяются по реестру танков, расчёты не выполняются.
- `GET /api/v1/vessels/{vessel_id}/loading-conditions` — список условий судна.
- `GET /api/v1/loading-conditions/{condition_id}` — получить условие и его исходные строки.
- `POST /api/v1/calculations/loading-condition` — выполнить и сохранить предварительный расчёт из источнико-помеченных весов, lightship и гидростатической таблицы.
- `GET /api/v1/vessels/{vessel_id}/calculation-runs` — история расчётов выбранного судна.
- `GET /api/v1/calculation-runs/{run_id}` — неизменяемый снимок входов, источников, предупреждений и результатов.

Проверки:

```bash
pytest -q
ruff check app tests migrations
```

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Vite запускается по адресу `http://localhost:5173`.

Во время локальной разработки Vite проксирует запросы `/api` и `/health` на `http://127.0.0.1:8000`. Поэтому сначала запустите backend, затем frontend. Публикация frontend на GitHub Pages размещает только статические файлы интерфейса: локальная SQLite-база и FastAPI автоматически в интернет не публикуются. Для работы с данными из опубликованного сайта потребуется отдельно развернуть backend с постоянным хранилищем и настроить защищённое соединение.

## Принципы разработки

1. Внутренние единицы — SI; преобразования только на границах ввода/вывода.
2. Каждое значение должно иметь единицу измерения, источник и статус проверки.
3. Нельзя экстраполировать за пределы утверждённых таблиц без отдельного валидированного метода.
4. Отсутствующие, противоречивые или выходящие за диапазон данные блокируют расчёт.
5. Расчёты должны быть детерминированными и проверяться на независимых эталонных примерах.
6. Критерии нормативной оценки настраиваются под конкретное судно; универсальный pass/fail не допускается.
7. В отчётах различаются рассчитанные, импортированные, предположительные и введённые пользователем значения.
8. Успешные программные тесты не доказывают безопасность судна или одобрение приложения.

## Безопасность и валидация

Перед реализацией расчётных функций необходимо изучить [SAFETY_AND_VALIDATION](docs/SAFETY_AND_VALIDATION.md). Эксплуатационное применение потребует независимой инженерной проверки и применимых одобрений флага, классификационного общества и компании.
